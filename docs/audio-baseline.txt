3. card1（aw883xx）关键控制 —— ★ 这就是「系统音量」
--------------------------------------------------------------------------------
$ amixer -c 1 cget numid=54
numid=54,iface=MIXER,name='Master Playback Volume'
  ; type=INTEGER,access=rw------,values=2,min=0,max=255,step=1
  : values=0,0                    <-- 空闲态 = 0（用户此时系统音量就是 0）

$ amixer -c 1 cget numid=19   -> Master / Slave Mode Select : values=1 (Master)
$ amixer -c 1 cget numid=47   -> Headphone Switch           : values=on

★ 解析注意：cget 输出里有两行带 "values="。
    `; type=INTEGER,...,values=2,...` 里的 2 是**声道数**，
    `: values=0,0` 才是**当前值**。
  只匹配 "values=" 会把音量读成 2。必须匹配行首带冒号的 ": values="。

4. 为什么 card1 numid=54 就是「系统音量」—— 三条独立证据
--------------------------------------------------------------------------------
证据 A：/etc/asound.conf 的软音量绑在 card1 上
  pcm.!default  = asym，playback.pcm = "speaker"
  pcm.speaker   = plug -> spk_softvol
  pcm.spk_softvol = softvol {
        control { name "Master Playback Volume" card 1 device 0 }
        min_dB -46.08  max_dB -0.18  resolution 256
        slave.pcm "resample_spk"   -> hw:1,0, rate 48000, 2ch
  }
  => /bin/aplay 不带 -D 时走 !default，**音量环节是 card1 的 softvol**，
     最终直接写 hw:1,0。声音根本不经过 rk817 的模拟输出级。

证据 B：hal-audio 的配置里写死了 numid
  $ /bin/hal-audio -l  (youdao_hal_config_get)
    speaker_card_id=1
    speaker_subdevice_id=0
    speaker_vol_ctl_numid=54        <-- 系统音量控件 = card1 numid 54
    mic_card_id=0
    analog_*_hs_vol_ctl_numid=51
    digital_hs_card_id=2
    enable_rk_aac=true

证据 C：改系统音量只动这一个控件（diff 实验）
  $ hal-audio -s 50
  $ (改前/改后各抓一次 `amixer -c 0 contents` + `amixer -c 1 contents`，全量 diff)
  => 只有 card1 numid=54 变化：values=0,0 -> values=176,176
     card0 的所有控件（含 Playback Path / Master / Speaker Switch）**一个都没变**

  映射实测（非线性）：
    hal-audio -s 0   -> card1#54 = 0,0
    hal-audio -s 30  -> card1#54 = 128,128
    hal-audio -s 50  -> card1#54 = 176,176
    hal-audio -s 100 -> card1#54 = 255,255

  ★ hal-audio -g 是坏接口，不能用来判音量：
      mixer 是 176,176 时 `-g` 返回 0；mixer 是 0,0 时 `-g` 也返回 0。
      判音量只能 `amixer -c 1 cget numid=54`。`-s` 本身是可靠的。

5. 声学 2×2 矩阵 —— 证明「响度只由 card1 决定，Playback Path 无关」
--------------------------------------------------------------------------------
方法：`aplay -q -t raw -f S16_LE -r 48000 -c 2 - < /dev/urandom` 播放 2 秒，
      同时 `arecord -q -D hw:0,0 -t raw -f S16_LE -r 48000 -c 2 -d 2` 录音，
      再用 od + awk 算 16bit 采样的绝对值均值 / 峰值。
前置：录音要先拨 `amixer -c 0 cset name="Capture MIC Path" "Main Mic"`（numid=46 0->1）。

  quiet（完全不放音）                  avg=83    max=240     <- 本底噪声
  Playback Path=OFF, amp=0,0           avg=90    max=553     <- 静音
  Playback Path=OFF, amp=200,200       avg=9339  max=32768   <- 大声 ★
  Playback Path=SPK, amp=0,0           avg=102   max=605     <- 静音
  Playback Path=SPK, amp=200,200       avg=9366  max=32768   <- 大声

结论：
  * OFF 与 SPK 对「是否出声」**没有任何差别**（90 vs 102，都在本底噪声量级）。
  * 唯一的开关是 card1 numid=54：0,0 -> 静音（90/102）；200,200 -> 满响度（9339/9366）。
  * 旧代码在系统音量为 0 时做的正是 `values=0,0 -> cset 200,200`，
    也就是把第 2 行变成第 3 行 —— **这就是用户听到的那声不该有的声音**。

6. 谁在管 Playback Path —— 没有系统守护进程
--------------------------------------------------------------------------------
对设备上所有可能碰音频的二进制做 `strings | grep -c "Playback Path"`：
  /bin/hal-audio                          -> 0
  /usr/bin/miniapp                        -> 0
  /usr/bin/weston                         -> 0
  /usr/bin/runSoundPlayer                 -> 0
  /oem/YoudaoDictPen/output/SoundPlayer   -> 0
  /oem/YoudaoDictPen/output/SoundRecord   -> 0
  /data/local/bluealsa_custom/bluealsa_orig -> 0

=> 没有别的进程会替我们拨/还原这个控件。我们改的，只有我们还原。

`/usr/lib/libydhal_devices.so` 里有音量子系统（set_volume_lock / volume_ctrl /
_volume_control_work / load_volume_from_sysconf / get_volume_numid_by_device_type_id），
映射它的进程：ResourceManager(1244)、SoundPlayer(1279)、SoundRecord(1316)、
input_subsytem_monitor(1365)、CaptureFrame(1504)、ota_mgr(1524)、miniapp(968)。
=> 音量键走 input_subsytem_monitor -> libydhal_devices -> hal-audio -s -> card1#54。

  async / blocksize / enable-last-sample / fd / last-sample / max-bitrate /
  max-lateness / name / parent / processing-deadline / qos / render-delay /
  stats / sync / throttle-time / ts-offset
=> **没有 close-fd 属性**，fdsink 不会替我们关管道写端，必须自己 close()。

  （-c 1 会报 "Channels count non available"）
